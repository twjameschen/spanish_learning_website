# Camino a Quito · 西班牙文之路

一套**完全離線**的西班牙文學習網站，語言變體鎖定**拉丁美洲 / 厄瓜多 Sierra（基多）**，
說明與解說可在**繁體中文 ↔ English** 之間切換，從 A0 讀到 B1。

無後端、無 API 呼叫、無 CDN、無 Google Fonts —— 所有字型、資料、圖示都打包進 build 產物。

> **目前進度：全部 7 個 Phase 完成**
> A0 到 B1 共 **41 課、728 個詞條、389 題**，五座城市全部開放。
> 間隔複習（FSRS）、7 種題型、XP／等級／連續天數／26 個成就、
> 旅程地圖、學習統計儀表板、匯出匯入都可以用了，全部中英雙語。

## 快速開始

```bash
npm install
npm run dev          # 開發伺服器 http://localhost:5173
```

## Build 與開啟方式

### 方式一：一般 build + 本機伺服器（**建議**）

```bash
npm run build
cd dist
python -m http.server 8000
```

然後用 Chrome / Edge 開 <http://localhost:8000>。

Windows 若 `python` 不存在，試 `py -m http.server 8000`；
沒有 Python 也可以用 `npx serve dist` 或 `npm run preview`。

### 方式二：單一 HTML 檔（雙擊即開）

```bash
npm run build:single
```

產出 `dist-single/index.html` —— **整個 app 就這一個檔案**（約 1.8 MB），
JS / CSS / 字型全部 inline 成 data URI。複製到隨身碟、雙擊就能用，不需要任何伺服器。

實測 Chrome / Edge 在 `file://` 下**可以**正常保存進度。
但若你的瀏覽器或設定不允許（無痕模式、停用網站資料、Firefox 擋 IndexedDB），
app 會自動降級成「記憶體模式」並在頂端顯示警示條 —— 此時進度**不會**自動保存，
離開前請按「匯出進度」。

## 進度怎麼存、怎麼備份

儲存層會自動偵測並選用可用的方式，**實際寫一次**來判斷，不是靠 protocol 猜：

| 層級 | 說明 |
|---|---|
| **IndexedDB** | 最理想。容量充裕，進度自動保存。 |
| **localStorage** | 退而求其次。可用但約 5 MB 上限，建議定期匯出。 |
| **記憶體** | 前兩者都寫不進去時的退路。功能完整，但**關掉分頁就沒了**。 |

目前生效的是哪一層，首頁「儲存方式」卡片會直接標示。

### 備份

- **自動快照**：每次開站自動存一份，每天一份、保留最近 3 天。
  瀏覽器誤清資料時可以救回來 —— 首頁「儲存方式」卡片的每一列都有
  「還原」，兩段式確認（點一下先問「確定要還原到這一天？」，再按確定才動手）。
- **手動匯出／匯入**：同一張卡片有按鈕。
  匯出的 `camino-progress-*.json` 可以帶著走，換電腦或換瀏覽器時匯入即可接續。
  匯入預設是 **replace**（先清空再寫入），避免新舊資料混在一起。

匯入與還原都會**立刻生效**，不必重新整理。這一點不是順手做的：
寫進儲存層之後如果沒有把記憶體裡的 store 補水
（`refreshStoresAfterImport()`），畫面會停在舊數字，
而且下一次作答就把整份舊進度寫回去，把剛匯入的資料靜靜蓋掉。
`replace` 模式下備份檔若沒有 `progress` 這個 key，會先把進度清成預設值
再補水 —— 否則舊進度會因為「沒有東西可以覆蓋」而留下來。

> 注意：`file://` 下 Chrome 把所有本機 HTML 檔案視為同一個來源，
> 也就是說單檔版的進度跟你電腦上其他本機網頁共用同一份儲存空間。
> 個人自用沒問題，但這也是建議用方式一的理由之一。

## 語言規範（貫穿全站）

- **絕不出現 vosotros**。複數第二人稱一律 `ustedes`（有測試把關，違反就 build 失敗）
- 動詞人稱只有 5 個：`yo` / `tú` / `él-ella-usted` / `nosotros` / `ellos-ustedes`
- 沒有 voseo（不教阿根廷的 `vos`）；厄瓜多以 `tú` / `usted` 為主
- 發音走 seseo（`c`/`z` 唸 /s/，沒有 /θ/）與 yeísmo
- 區域用法只要不是百分之百確定，一律標 `needsVerify: true`，UI 上顯示「待母語者確認」小標記

### 錯題本

答錯的題目會收進首頁的「錯題本」，**答對之後自動消失**。
判定只看每一題**最近一次**作答，所以不必另外記一份「已訂正」的狀態，
也就不會有兩份資料對不起來的問題。

四種來源的題目都進得了錯題本 —— 課程練習、連續聽寫、陰陽性分類、單字閃卡。
把卡片對回題目的那段程式在 `src/lib/cardResolve.ts`，複習佇列也共用它。

> 這裡順手修掉一個既有的落差：複習頁原本只認得課文裡手寫的題目與**手寫的 5 張閃卡**，
> 但單字閃卡練習會為任何單字建立卡片。於是首頁說「今天要複習 20 張」、
> 點進去卻只剩幾張。四種來源補齊之後就對得上了。
>
> 首頁那個數字現在也直接用佇列長度算（`src/lib/review.ts`），
> 不再各算各的 —— 內容改版後留下的孤兒卡片不會再被多算進去。

### 單字與例句都能點來聽

單字表的每個字、它的例句、課文裡每一句規則例句旁邊都有一顆小喇叭。
裝置偵測不到西班牙文語音（或在設定裡關掉語音）時**整顆不顯示** ——
按了沒反應的按鈕比沒有按鈕更糟。

「有沒有西班牙文語音」是全域的一件事，所以偵測結果共用一份
（`src/lib/speech.ts`）。單字表一頁會掛 1456 顆喇叭，各問各的話就是
1456 個 `voiceschanged` 監聽器加 1456 個 timeout 掛在同一個物件上。

### 單字表為什麼是一頁到底

單字表把符合條件的字**全部**渲染，沒有分頁也沒有虛擬捲動 ——
沒篩選時就是 728 張卡、1456 顆喇叭。換來的是 Ctrl+F 一次找得完整頁，
代價則要靠三件事壓下來（都沒有加新套件）：

- `WordCard` 與 `SpeakButton` 包 `React.memo`：搜尋框每按一個鍵不再重繪全部卡片
- 清單的 key 就是 `w.id`，不加 locale 前綴：切換語言不會整頁重掛 1456 顆喇叭
- 卡片開 `content-visibility: auto` 搭 `contain-intrinsic-size`：
  畫面外的卡片跳過版面與繪製，內容仍留在 DOM 裡

實測（`scripts/e2e/vocab-perf.mjs`，728 張卡全開）：

| | 改動前 | 改動後 |
|---|---|---|
| 打字最慢一次 | 172 ms | 27 ms |
| 連打六個字總計 | 361 ms | 151 ms |
| 切換語言 | 677 ms | 70 ms |

切換語言那一格才是原本真正卡的地方 —— 打字其實只有第一次比較久。

### 打不出西文字元的時候

作答的輸入框上方有一列 `á é í ó ú ü ñ ¿ ¡`，點一下**插在游標位置**
（不是接在最後，所以在句子中間補一個重音字母不必重打後半段）。
重音其實可以不打（比對時會折掉），但 **ñ 不折** —— año 與 ano 是兩個字。

### 想不出來的時候怎麼辦

聽力、翻譯、變位填空這三種題型的送出鍵在沒打字時是停用的，
所以完全想不出來的話會**整題卡死** —— 只能亂打一通讓它判錯才過得去。
三種的輸入框下方因此都有兩階求助（`Shared.tsx` 的 `HelpRow`）：

| 第一階 | 給什麼 | 用在哪 |
|---|---|---|
| **看中文意思** | 只翻出意思，西文自己拼 | 聽力題 |
| **看提示** | 答案的骨架：每個字只留第一個字母（`M· l···· A··.`） | 翻譯題、變位填空 |

翻譯題的題面本來就是意思、變位題畫面上已經有原形＋人稱＋時態，
所以那兩種給的是形狀而不是意思。骨架由 `src/lib/skeleton.ts` 產生，
標點原樣保留（`¿D···· e··· e· b···?`），首字母的重音也留著 —— 提示要誠實。

| 第二階 | 給什麼 | 怎麼算分 |
|---|---|---|
| **直接看答案** | 正解由回饋面板印出來 | 算答錯、0 XP，跟閃卡的「想不起來」同一個意思 |

用了第一階之後即使答對也記 `hesitant`，FSRS 給 Hard 而不是 Good，
那一題會比較快再出現。第二階則直接算答錯。

裝置沒有西班牙文語音時，聽力題本來就會改成看著西班牙文抄寫，
整句已經在畫面上，那時**不顯示求助按鈕**。

### 設定放在哪裡

右上角的齒輪。三個設定在 Phase 10 之前存在資料層卻沒有任何畫面入口 ——
每日目標永遠鎖在 5 分鐘、語音關不掉、「未經確認的區域用法」那個開關
甚至沒有任何地方在讀。

| 設定 | 選項 |
|---|---|
| 每日目標 | 5 / 10 / 15 分鐘（首頁的連續天數卡以這個數字算達標） |
| 西班牙文語音 | 開／關（關掉後聽力題改成抄寫，題目不會消失） |
| 未經確認的區域用法 | 顯示／隱藏 |
| 介面與解說語言 | 中文／English（header 也有快捷鍵） |
| 主題 | 淺色／深色／跟隨系統（header 也有快捷鍵） |

「未經確認的區域用法」選隱藏時**整塊都不顯示**，不是只把「待母語者確認」
的標記藏起來 —— 那會讓沒把握的用法看起來像已經確認過的，
正好違反規格第七條的誠實要求。要嘛看到內容連同警告，要嘛看不到。

### 連續聽寫的題庫從哪來

課內的聽力題受規格「每課 6–10 題」限制，補不上去了（41 課裡 30 課已滿），
所以整句聽寫另外做成課外模式，不佔課程題數。

題庫**不另外寫句子**，而是從已經審過的內容組起來：課內 44 題聽力，
加上課文規則裡的例句。例句要過三關才進題庫 —— 是完整的一句話
（句尾有 `.!?` 或句首有 `¿¡`）、不是變化表展示（`hablar → hablando`）、
不是對話（`Gracias. — De nada.` 中間的破折號聽不出來也打不出來）。
同一句話課內有手寫版本時用手寫的那一版，說明比較好，FSRS 也記在同一張卡上。

濾完 **321 句**：邁阿密 28 · 基多 111 · 昆卡 107 · 加拉巴哥 67。
台北那六課教的是字母與發音，例句多半是單字與片語，湊不滿一場，所以那一段沒有入口。

`accept` 由程式自動補齊三種變體的交叉組合 —— 去 ñ、去逗號、去句中的 `?!`。
這三種 `normalizeAnswer()` 不會處理，而聽的人也沒辦法從聲音判斷要不要打。

### 掌握度星等從哪裡來

每個單字的 0–5 星是 FSRS 的 stability 映射出來的，而 stability 只有在
**單字閃卡**裡才會累積 —— 一般的四選一、翻譯題算的是「這一題」的熟練度，
不是「這個字」的。所以想看到詞性雷達與最弱十個字有資料，要做單字閃卡。

### 鍵盤快捷鍵

| 鍵 | 動作 |
|---|---|
| `1`–`4` | 選四選一的答案 |
| `Space` | 翻開閃卡 |
| `1` / `2` | 翻開後：想不起來／我記得 |

## 語言切換

右上角的 **中／EN** 按鈕一次切換**全部** —— 介面、單字字義、例句翻譯、
課文、題目解釋都跟著換。設定會存進儲存層，重整後保持。

西班牙文本身（單字、例句、變位表）當然不隨語言改變，那是要學的東西。

### 為什麼兩種語言都強制必填

`schema.ts` 的 `localizedSchema` 要求 `{ zh, en }` 兩邊都非空。
刻意不做「缺英文就 fallback 回中文」—— 那樣切到英文時會看到一半中文一半英文，
比整頁中文更難用。缺翻譯就讓驗證失敗，`npm run build` 直接擋下。

`src/i18n/i18n.test.ts` 另外檢查：
所有 1,306 組欄位兩邊都在、英文欄位不含中文字、
該翻譯的欄位沒有兩版一模一樣（純數字與注音式重音標記如 `CA-sa`、`/k/` 除外）。

## 自己新增單字

內容全部是 `src/content/` 下的純 JSON，由 `src/content/schema.ts` 的 zod schema 驗證。
**schema 不符會讓 `npm run build` 直接失敗**，不會默默出錯。

### 加一個名詞

編輯 `src/content/words/a0.json`，加一筆：

```json
{
  "id": "ventana",
  "es": "ventana",
  "gloss": { "zh": "窗戶", "en": "window" },
  "pos": "noun",
  "gender": "f",
  "level": "A0",
  "topic": "lugares",
  "exampleEs": "La ventana es grande.",
  "exampleGloss": { "zh": "那扇窗很大。", "en": "The window is big." }
}
```

必填欄位：`id`（小寫、數字、連字號）、`es`、`gloss`、`pos`、`level`、`topic`、
`exampleEs`、`exampleGloss`。

**所有給人看的文字都是 `{ zh, en }` 物件，兩邊都必填。**

**`pos` 是 `noun` 時 `gender` 必填**（`m` 或 `f`）—— 這條由 schema 強制，
因為中文沒有性別，這是最容易漏的欄位。反過來，非名詞不准標 `gender`。

選填：`genderNote`（陰陽同形或例外時說明）、`regional`（區域用法）。

### 加一個動詞

編輯 `src/content/verbs/a0.json`。動詞多幾個欄位：

```json
{
  "id": "abrir", "es": "abrir",
  "gloss": { "zh": "打開", "en": "to open" },
  "pos": "verb", "level": "A0", "topic": "verbos",
  "exampleEs": "Abro la ventana.",
  "exampleGloss": { "zh": "我打開窗戶。", "en": "I open the window." },
  "infinitive": "abrir", "irregular": false, "reflexive": false,
  "participio": "abierto", "gerundio": "abriendo",
  "conjugations": {
    "presente": {
      "yo": "abro", "tu": "abres", "el_ella_usted": "abre",
      "nosotros": "abrimos", "ellos_ustedes": "abren"
    }
  }
}
```

**人稱只有這 5 個 key，多一個少一個都會驗證失敗。** 沒有 vosotros。
`presente` 必填，其他時態選填。

### 加一個區域用法

```json
"regional": {
  "region": "Ecuador",
  "note": {
    "zh": "厄瓜多常用，其他西語區多說 …",
    "en": "Common in Ecuador; elsewhere people usually say …"
  },
  "needsVerify": true
}
```

`region` 只能是 `Ecuador` / `Andes` / `LatAm` / `Quito` / `Costa`。
**不是百分之百確定就設 `needsVerify: true`** —— UI 會顯示「待母語者確認」標記，
誠實標示不確定比假裝權威有用得多。

### 改完之後

```bash
npm run validate:content   # 只跑內容驗證，最快
npm test                   # 全部測試
```

驗證會檢查：schema 形狀、id 唯一、名詞有性別、例句非空、每題都有解釋、
**中英兩種語言都不缺**、跨檔引用都解析得到（題目指向的單字要存在、
變位題答案要跟變化表一致）、前置課程無循環，
**每課 6–10 題且至少有一題聽力**、聽寫題的 `accept` 有無 ñ 與無逗號的版本，
以及**沒有任何 vosotros 或 voseo 形式混進來**。

## 內容結構

```
src/content/
├─ schema.ts        zod schema —— 型別的單一真相來源（TS 型別由 z.infer 反推）
├─ index.ts         載入 + 驗證 + 跨檔完整性檢查
├─ words/{a0,a1,a2,b1}.json   非動詞詞條，共 623 個
├─ verbs/{a0,a1,a2,b1}.json   動詞，共 105 個（含變化表）
├─ lessons/{a0,a1,a2,b1}.json 課程，共 41 課
└─ journey.json               5 個城市 → 課程分組

src/i18n/
├─ ui.ts            介面字串（按鈕、標題、狀態訊息）
└─ index.ts         useT()：t() 取介面字串、L() 取內容的 Localized 欄位
```

每一課的結構：

| 欄位 | 用途 |
|---|---|
| `intro` | 白話的中文導言 |
| `rules[]` | 規則 + 雙語例句 |
| `pitfalls` | **最容易犯的錯，明講** —— 這是全站最重要的教學資產 |
| `pronunciation[]` | 發音課專用：字母、IPA、中文說明、例字 |
| `exercises[]` | 練習題，7 種題型 |
| `prerequisites[]` | 前置課程 id，用於技能樹解鎖 |
| `usesOnlyTaughtGrammar` | 自我聲明：規則例句只用了本課與前置課教過的文法 |

### pitfalls 的撰寫口吻

**直接講西班牙文本身的規則與陷阱，不拿其他語言的情境來對照。**

結構固定為：點出最容易犯的錯 → `✗ / ✓` 具體示範 → 可操作的判準 → 自我檢查法。

`src/content/no-vosotros.test.ts` 有兩支測試把關：
禁止以其他語言為參照的詞彙、每課都必須有 `✗/✓` 對照。

### 例句難度政策

- **單字例句實用優先** —— 用真的會用到的日常句，即使用到之後才教的文法
  （例如 `¿Cuánto cuesta?` 當整句記憶）。
- **課文例句嚴格分級** —— 示範文法規則的例句只用該課與前置課教過的東西，
  讓規則被孤立出來、不被雜訊干擾。

## 品質閘門

`npm test` 跑的 780 條測試裡，有一批是專門用來擋內容錯誤的 ——
它們的存在理由是「這種錯誤看不出來，但學習者會學到錯的東西」。

| 測試 | 擋什麼 |
|---|---|
| `no-vosotros.test.ts` | 任何 `vosotros`／`vuestro`／voseo 的痕跡；變位表的人稱 key 必須**恰好**是那 5 個 |
| `schema.test.ts` | zod 驗證、id 全域唯一、**名詞性別符合字尾規則**（例外要明列理由）、markdown 只用渲染器支援的語法 |
| `irregular-verbs.test.ts` | 15 個不規則動詞的現在式與簡單過去式逐格比對；其餘時態用西班牙文本身的結構規律驗（未來式與條件式同字根、過去虛擬式由簡單過去式第三人稱複數推出…） |
| `conjugate.test.ts` | 規則變位引擎，含正字法調整（`buscar → busqué`、`creer → creído`） |
| `normalize.test.ts` | 大小寫／重音折疊，且 **`año` 不會被折成 `ano`** |
| 完整性檢查 | 跨檔引用（`wordId`／`verbId` 存在、`genderSort` 的字都是名詞且**兩個冠詞不能都對**）、前置課程無循環 |

幾條測試是**先發現真實錯誤才寫出來的**，不是事後補的：
引擎的 `participio()` 少了遏止重音（`creer → creido`）、`parseVerb()` 不接受 `-ír` 結尾、
`llover` 被硬填出 `lluevo` 這種不存在的形式。

有一類 bug 單元測試抓不到，得在瀏覽器裡跑才看得見，`scripts/e2e/` 因此存在：
設定對話框被祖先的 `backdrop-filter` 夾成 64 px 高、
單字表 1456 顆喇叭在共用偵測結果之後只剩第一顆活著、
以及匯入備份顯示「成功」但畫面停在舊數字、下一次作答又把舊進度寫回去 ——
這三個在 jsdom 裡全都是綠的。

另外幾條是**測試自己先騙過關**才發現的：

- 「只有一題的練習按『再練一次』會卡死」。重來只重設了 `index`，
  一題的時候 `setIndex(0)` 是 no-op，掛在 `[index]` 的重設 effect 不會再跑，
  `outcome` 活了下來 —— 題目變成攤開又不能作答，只能在結算與那一題之間
  來回彈。每一組陰陽性分類都恰好是一題，所以一定會被踩到。
  當時那條測試用的正好也是一題卻**過關**，因為它只看了「1/1」與結算消失，
  從來沒問過「那一題還能不能作答」
- **effect 掛到會變動的值上**：聽力題的重設 effect 依賴 `speech.available`，
  而它在同一題進行中會翻轉兩次（語音偵測最多等 2 秒才完成、
  設定裡的語音開關也會即時改它），兩條路徑都會把使用者**打好的字清空**
- **快捷鍵穿透對話框**：快捷鍵說明面板上就列著「1～4 選答案」，
  照著按下去會替使用者回答**背後那一題**、寫進一次 FSRS 複習、然後跳下一題
- **同一課在兩個畫面上有兩個編號**：Phase 18 給首頁加了「繼續：第 N 課」，
  用的是 journey 的正式順序，但課文頁的徽章一直印 `lesson.order`
  —— 那是每個城市各自從 1 開始編的。於是首頁說「繼續：第 41 課」，
  點進去卻寫「第 6 課」。**這一個是加首頁那顆按鈕時自己造出來的** ——
  剛在同一輪把 `order` 認定成不能拿來排全部課程，卻漏了課文頁也在印它
- **一顆永遠亮著、而且沒人查核的綠色徽章**：課文頁的「例句嚴格分級」由
  `usesOnlyTaughtGrammar` 驅動，但 41 課全部宣告 `true`
  —— 它分辨不出任何東西，還把作者自述畫成已驗證的屬性
- **分頁標題與 `<html lang>` 都寫死在 `index.html`**：16 條路由共用同一個
  `<title>`，桌機開一排分頁時每一個都長一樣，分不出哪個是單字表哪個是
  練習，瀏覽記錄與書籤也全部同名。同一個地方的 `lang="zh-Hant"` 不跟著
  語言開關走 —— 切成英文之後讀屏仍用中文語音唸英文介面，
  英文模式下等於 WCAG 3.1.1（Language of Page）不合格。
  兩個都改由 `useDocumentMeta()` 依路由與語言產生
- **課程的「上一課／下一課」跳級**：課文頁拿 `lesson.order` 排全部 41 課
  來算前後鄰居，但那個欄位是**每個城市各自從 1 開始編**的
  （41 課只有 13 個相異值）。於是五個城市的第 1 課被排在一起 ——
  A0 第 1 課的「下一課」是 A1 的反身動詞、「上一課」是 B1 的過去虛擬式。
  初學者照著按就直接掉出 A0。這條路徑從 Phase 5 就是壞的，
  一路沒被發現是因為**沒有任何測試碰過課程順序**。
  正確順序是 journey 各站的 `lessonIds` 接起來（`orderedLessons`），
  現在有 13 條測試釘著，包含那個症狀本身

### 課程編號只有一套

課有兩種編號，很容易搞混：`lesson.order` 是**每個城市各自從 1 開始編**的，
而「第幾課」對學習者的意思是**整條路上的第幾課**。

- **課程列表**印 `lesson.order` —— 那裡的課排在城市標題底下，
  「1, 2, 3…」讀得出是那一站的第幾課
- **課文頁**與**首頁的「繼續」**印正式順序的位置，帶總數（`第 41 / 41 課`）

Phase 18 加首頁「繼續：第 N 課」時漏了課文頁，於是同一課在兩個畫面上有兩個
編號：首頁說「繼續：第 41 課」，點進去卻寫「第 6 課」。
`src/pages/LessonPage.test.tsx` 現在把兩邊釘在一起。

### 例句的寫作準則（以及為什麼它不是一顆徽章）

**課文示範文法規則的例句，只使用本課與前置課教過的文法。**
（單字表的 `exampleEs` 不受此限 —— 那邊實用優先。）

這條準則以前是課文頁上一顆綠色的「例句嚴格分級」徽章，由每一課的
`usesOnlyTaughtGrammar` 驅動。那顆徽章拿掉了，因為它有兩個問題：
**41 課全部宣告 `true`**，所以它永遠是亮的、分辨不出任何東西；
而且它把一個沒有任何東西查核的作者自述，呈現得像已經驗證過的屬性 ——
規格的內容誠實原則不允許這樣。

有試過用 `verbForms.ts` 的變位反查索引機械驗證它，**做不到**：
`de`（dar 的現在虛擬式）、`cómo`（折重音後撞到 `como`）這類同形字會產生
大量假陽性；而 A0 例句裡的 `Soy`、`Tengo` 出現在「現在式」那一課之前
其實是對的 —— `a0-ser-estar` 本來就在教那些形式。要分辨「當成系統教的時態」
與「當成固定說法教的個別形式」，資料裡沒有足夠的資訊。
所以準則留在這裡當寫作規範，欄位留給作者自己看，不再假裝它被驗證過。

### 為什麼 `prerequisites` 不顯示在畫面上

40 課宣告了 `prerequisites`，資料是乾淨的（沒有懸空引用，也沒有跟正式順序
矛盾），但**41 課裡有 39 課的前置就是正式順序的前一課** —— 跟課文頁已經有的
「上一課」連結完全重複。只有 `a1-presente-regular` 一課的前置是非相鄰的
（`a0-ser-estar`，跳過了 `a0-hay`）。

把它畫出來會在 39 個頁面上加一行沒有新資訊的字。它真正的用途是內容驗證：
`checkContentIntegrity()` 用它擋懸空引用與循環相依。

### README 的數字不會再說謊

上面那張統計表全靠手維護，而且**已經漂移過**：Phase 16 之前它寫著
「105 個，其中 15 個高頻不規則動詞補齊 7 個簡單時態」—— 實際上 105 個
全部都有 7 個時態，不規則的是 49 個。錯的數字比沒有數字更糟，
因為它讀起來像已經查證過。

`src/content/readme-numbers.test.ts` 把每一格接回真正的來源（詞條、動詞、
課程、題型分佈、聽寫題庫、成就、區域標註）。改了內容忘了改 README 就會紅，
而且錯誤訊息直接說出該填多少。它跑在 `npm run validate:content` 裡，
所以**數字錯了連 build 都不會過**。

### 兩條規格規則的閘門

規格裡有兩條關於區域用法的硬性規則，在此之前沒有任何測試把關
（`src/content/regional-rules.test.ts`）：

- **`-ito/-ita` 指小詞**。作法不是禁止出現 —— 那反而會讓教材躲開最該講的
  東西。規則是**出現就必須解釋**：單字表裡的指小詞被釘成一組白名單
  （目前只有 `ahorita` 與 `un ratito`），多一個就會紅，逼下一次做一個
  有意識的決定；而且說明必須講「軟化語氣」而不是「比較小」——
  把 `un cafecito` 講成「小杯咖啡」就是教錯
- **`ahorita` 的時間模糊性**。說明要同時講到「立刻」與「等一下」兩種可能，
  不能只給一個翻譯；課文的 pitfalls 也必須把「當成立刻」列為會犯的錯

### 一課接一課

學完一課之後要往哪裡去，以前畫面上沒有答案：結算只有「再練一次」與
「回到課文」兩條回頭路，首頁六張卡全是分類入口。隔一天回來的人得先點進
課程列表、再自己回想上次做到哪一課。

現在有兩個入口，兩個都走 journey 的順序（不是 `lesson.order`，見上）：

- **首頁 hero 的「繼續：第 N 課」** —— `firstUnfinishedLesson()` 找的是
  **最前面那一堂還沒做的課**，不是接在最後做過的那一堂後面。跳著做的人
  會被帶回前面的洞，而不是把洞留在那裡。41 課都做完就換成建議複習
- **結算畫面的「下一課：〇〇〇」** —— 連到下一課的**課文**而不是直接跳進
  題目：新的一課要先讀過規則與陷阱，直接丟進題目裡只會變成猜。
  答對不到六成時「下一課」退成次要按鈕、「再練一次」變主要 ——
  這一輪還沒站穩，往前推只是把洞帶著走。最後一課不給按鈕，給一句話

### 動詞變位表怎麼查

105 個動詞每一個都有 7 個簡單時態。這在 Phase 16 之前是**資料裡有、
畫面上沒有**：唯一印得出來的是單字表的現在式，3675 個形式只看得到 525 個
（86% 看不到），而 73 題變位題裡有 44 題考的正是那些查不到的時態。

`#/verbs` 是列表，`#/verbs/:id` 是完整的表。時態與人稱標籤直接用現成的
`TENSE_LABEL` 與 `PERSON_LABEL`，**沒有新增任何內容資料**。

搜尋框吃**已經變過位的形式**：打 `fui` 會同時找到 `ser` 與 `ir`，
並在兩列上各標「fui＝簡單過去式・我」。反查表在
`src/lib/verbForms.ts`，模組載入時掃一次資料建成，4083 個形式全部進索引
（有一條測試逐格核對，一格都不能漏）。

兩個實作上的坑值得記著：

- **反身動詞在 JSON 裡存的是連代名詞的完整形式**（`llamarse` 的 yo 是
  `me llamo`）。只索引完整形式的話，打 `llamo` 會找不到 ——
  而學習者在課文裡看到的往往就是不帶代名詞的那半，所以兩種都索引
- **`haber`、`poder`、`preocuparse` 沒有命令式**，那三頁整區不顯示。
  不補、不編 —— 跟區域用法同一條原則

`src/lib/conjugate.ts` 不參與渲染。它是**編寫期的引擎兼驗證器**：
`irregular-verbs.test.ts` 用它重新推導形式來跟 JSON 對答案
（未來式與條件式同字根、過去虛擬由簡單過去第三人稱複數推出…）。
畫面要印的是 JSON，不是即時推導。

### 進度要顯示在你做決定的地方

有兩個地方一直是「app 要你達到某個數字，卻從來不告訴你單項進度」：

- **41 課的列表**看不出哪些做過、哪些全對，但 `completedAt` 與
  `bestAccuracy` 從 Phase 4 就寫進 store 了，而且有兩個成就就是
  「在 N 課中全部答對」
- **728 個字**沒有任何熟練度顯示，但 `starsForWord()`（0–5 星，
  由 FSRS 的 stability 換算）寫好也測過，又有兩個成就是「精通 N 個字」

現在課程列表上做過的課用打勾取代序號、全對的另外標「全對」、
沒全對的顯示最佳正確率，城市標題則是「做完 N / M 課」；
單字卡與動詞列上有 0–5 星的熟練度。

**0 星整個不顯示**。728 張卡裡絕大多數一開始都是 0 星，
每張都掛五顆空星只會變成視覺雜訊，而且會讓「還沒學過」跟
「學過但忘光了」看起來一樣 —— 前者不該被責備。

星等靠父層訂閱 `cards`、把數字當 prop 傳進 memo 過的卡片，
所以答完題回來會跟著變（直接在卡片裡呼叫 `starsForWord()` 不會 ——
它走 `getState()`，memo 過的卡片根本不會重繪）。

### 無障礙

所有頁面在**淺色與深色兩種模式**下都通過 WCAG AA 文字對比（一般文字 4.5:1、大字 3:1），
用瀏覽器實際量測而非目測。品牌橘 `#FF8A5B` 上的白字只有 2.32:1，
因此那些位置改用深墨色（5.56:1）—— 色票本身維持規格指定的值不變。
